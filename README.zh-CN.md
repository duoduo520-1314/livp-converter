# LIVP Converter

把手机拍的**动态照片 / 实况照片**（`.livp`）批量拆分成普通图片和视频。

Windows 11 双击即用，图形界面，无需命令行。

[English](README.md)

---

## 这是什么问题

用手机拍了「动态照片」，传到电脑 / 发给朋友后，文件后缀变成了 `.livp`。
这类图片**双击打不开**，微信、QQ、邮件、朋友圈也发不了 —— 因为它不是一种通用格式。

`.livp` 实际上是一个 **ZIP 压缩包**，里面装着两个东西：

```
xxx.livp
├── xxx.HEIC   ← 静态照片（主图）
└── xxx.MOV    ← 按下快门前后的那段短视频（约 3 秒，带声音）
```

把它拆开，就得到一张普通 JPG 和一段普通 MP4，任何设备都能用。

## 直接使用（推荐）

1. 到 [Releases](https://github.com/duoduo520-1314/livp-converter/releases) 下载 exe，
   **推荐 `LIVPConverter_v2.exe`**（界面已改版，见下文）；
   `LIVPConverter.exe` 是旧界面，留给习惯旧版的人
2. 双击运行，无需安装
3. 三步搞定：
   - **选择文件**（可多选）或 **选择文件夹**（自动递归查找所有 `.livp`）
   - **选择输出文件夹**
   - 点 **开始转换**

> Windows 首次运行会提示「未知发布者」，点「更多信息 → 仍要运行」即可。

### 需要先装 ffmpeg

本工具用 ffmpeg 做图片和视频转换，**请确保电脑已安装**：

```powershell
winget install Gyan.FFmpeg
```

或从 [ffmpeg.org/download.html](https://ffmpeg.org/download.html) 下载。

也可以直接把 `ffmpeg.exe` 放在本程序同一目录下。启动后日志区会显示「ffmpeg 引擎就绪」即表示成功。

## v2 界面改了什么

`LIVPConverter_v2.exe` 保留了下面**全部**功能，只重做界面，改的都是大批量转换时真会出问题的地方：

| 改动 | 解决什么 |
|---|---|
| **文件清单可见** | 以前选完文件夹只报一句「893 个」。v2 按相册列出张数与体积，开始前就能确认系统找到的是不是你要的那些 |
| **选项区可折叠，且记住状态** | 8 个复选框和画质滑块不再长期占着屏幕正中；折叠状态跨次启动保留 |
| **状态胶囊 + 百分比进度** | 显示 `75%　3 / 4　IMG_0421.livp`，状态按 空闲/忙碌/成功/失败 换色 |
| **主次动作分层** | 只有「开始转换」是强调按钮；「清除记录」移到右侧并加描边，误点代价高的不再挨着天天点的那个 |
| **窗口高度自适应内容** | 固定高度时日志区曾被压到 2px，等于没有。v2 按内容开窗并保证完整显示在屏幕内 |
| **输入框有边框** | 以前输出目录那个框和标签分不清 |

两个版本共用同一套转换代码：v2 继承 v1 的界面类，真正碰你文件的逻辑只有一份实现。

## 功能

| | |
|---|---|
| **选择单个 / 多个文件** | 支持按住 Ctrl / Shift 多选 |
| **选择整个文件夹** | 递归查找，自动保留原有子目录结构 |
| **断点续传** | 关掉程序再打开，自动恢复上次的文件列表与选项，接着没做完的继续 |
| **联系表** | 把转换结果生成一张可浏览的 HTML 缩略图页面，按相册分组，支持翻页或连续滚动 |
| **联系表进度** | 后台生成 + 进度条，中途可停止 |
| **按拍摄时间命名** | 产物名改为 `20260315_102333.jpg`，按 EXIF 拍摄时间而非 `IMG_1234` |
| **按日期分文件夹** | 可选，在相册目录下再分 `2026-03-15/` 子目录 |
| **跳过已转换** | 默认开启。输出已存在时不重复处理，中断后重跑不浪费时间 |
| **输出 JPG** | 取全尺寸主图，不是缩略图 |
| **输出 MP4** | 统一转 H.264，任何设备都能播放 |
| **输出 GIF** | 可选，勾选时会提示体积代价 |
| **保留原始文件** | 可选，同时保留 HEIC / MOV |
| **画质调节** | 1（最高画质）~ 8（最小体积） |
| **实时进度与日志** | 每个文件的转换结果一目了然 |
| **日志可筛选** | 按成功/失败/跳过分类筛选，颜色区分，一键复制失败项 |
| **耗时与体积预估** | 开始前就能看到这批要花多久、占多少磁盘，改任何选项都会重算 |
| **清理源文件** | 可选。转换成功后把 .livp 送入回收站，需二次确认 |
| **中途停止** | 随时可以停下来 |

> **目录结构**：默认保留你原有的相册目录（如 `2024云南2日游/`），只在目录内改名。
> *按日期分文件夹* **默认关闭** —— 多数人本就按相册整理，开了反而会把一个相册
> 打散进几十个日期目录。只有源文件完全没有有意义的目录结构时，才建议开启。

> **关于拍摄时间**：按以下优先级判定，转换日志里会标注每个文件时间的来源。
> 1. 照片 **EXIF** 中的 `DateTimeOriginal`（最准确）
> 2. **文件名**推断，如 `IMG_20260315_102333`
>
> 两者都读不到时，**保留原文件名**，并在汇总里报告受影响的数量。
> 这里**刻意不使用文件修改时间兜底** —— 它会被微信传输、备份还原、批量改名反复改写。
> 实测某数据集里它平均偏离真实拍摄时间 **54 年**，用它命名会产出
> 「看起来正常、实际全错」的文件名。
>
> HEIC 的 EXIF 存放在容器内部，本工具不做解析，这类文件改用文件名。
> 而绝大多数手机文件名本身就带时间戳，结果一致。日志中的 `[EXIF]` `[文件名]`
> 标签会如实告诉你该文件用了哪一级。
>
> 同一秒内的连拍会自动追加 `_2` `_3` 序号，不会互相覆盖。

> **关于 GIF**：动图生成慢（约 2.8 秒/个）且体积大（约 6 MB/个）。
> 勾选时会弹窗提示预计占用空间，可随时取消。

## 耗时与体积预估

操作按钮下方有一行预估，随文件增减、选项变更**立即重算** ——
勾上 GIF 或拖动画质滑块，数字立刻跟着变。

预估基于 893 张真实照片（17 个相册）的实测数据，综合考虑 JPG/MP4 基线、GIF 编码、
保留原始文件、画质设置，以及上次已完成、会跳过的数量。

> 它是**估算，不是承诺**。计算假设单文件开销大致恒定，因此一批异常大的 HEIC
> 实际会更慢。它的意义在于让你开始前就能判断这批值不值得跑 ——
> 「大约 1 小时、5.3 GB」是个有用的信息，而空进度条永远给不了。

## 读日志

893 张照片会产生 893 行结果，其中可能只有 4 行是失败的 —— 埋在第 4、217、450、832 行。
而 tkinter 的文本框本身没有查找功能，想找到它们只能拖滚动条，或者全选复制到别处搜。

现在日志区带筛选栏：

```
[ 全部 (892) ]  [ 成功 (880) ]  [ 失败 (4) ]  [ 跳过 (8) ]      复制失败项
```

点「失败」就只剩那 4 行。结果同时用**颜色区分** —— 成功绿、失败红、跳过橙 ——
即使停在「全部」模式，红色也会自己跳出来，不用点任何按钮。

两个值得知道的细节：

- **批次级信息始终可见**。筛到失败时，底部仍会保留「完成：成功 880，失败 4」——
  否则只剩 4 行红字、没有上下文，很容易误以为整批就只有 4 个文件。
- **复制失败项**一键把所有失败行放进剪贴板，方便贴到记事本或问题反馈里。

计数在转换过程中实时更新，可以中途点「失败」盯着失败项冒出来。
日志保留最近 4000 行，更早的自动裁掉，再大的批次也不会卡。

## 联系表

大批量转换完成后，翻文件夹找照片很累。点**生成联系表**会扫描输出目录，
生成一张 `index.html` —— 按相册分组、带缩略图、可搜索框筛选，点击看大图
（左右方向键翻页），用默认浏览器打开即可，离线可用。

缩略图由 ffmpeg 生成并缓存在 `.thumbs` 目录，增量转换后重新生成只会处理新照片。
893 张首次生成约需 3 分钟，生成的页面不到 1 MB。

### 生成过程

联系表在**后台线程**生成，窗口全程可响应 —— 可以拖动、翻日志、去忙别的。
独立的进度条显示 `342 / 893` 和当前处理的文件，旁边的**停止**按钮可以中途放弃。

中途停止是安全的：已生成的缩略图留在缓存里，下次接着用；也不会留下半成品
`index.html`。

日志会先说清这次到底要干多少活：

```
联系表：共 893 张，其中 45 张需新建缩略图（首次生成较慢，之后点一次很快）。
```

这个预扫描耗时不到10 毫秒。它有用是因为两种情况的体感天差地别 ——
新建 893 张要三分钟，而全部命中缓存时约 2 秒就结束。不区分的话，
第二次点按钮看起来就像程序没反应。

### 两种浏览模式

两种模式**都不会一次性把全部照片塞进 DOM**，这是 893 张（甚至上万张）依然流畅的原因。

| 模式 | 行为 | 适合 |
|---|---|---|
| **翻页浏览**（默认） | 每页固定张数 —— 60/ 120 / 240 / 480，页脚常驻首页/上一页/下一页/末页与跳页输入框 | 逐页挑选 |
| **连续滚动** | 滚动到底自动追加下一批 | 一口气快速翻完 |

分页按**照片张数**计算，相册标题不占名额 —— 所以「每页 120 张」永远是 120 张照片。
若某页恰好从相册中间开始，该相册标题会重复显示一次，避免失去位置感。

### 筛选

- **搜索框**：按文件名实时匹配
- **相册下拉**：只看某一个相册

两个筛选在两种模式下都生效，且**灯箱只在筛选结果内翻页** —— 方向键不会跳到你已经
筛掉的照片上。

### 灯箱

点击缩略图放大。左右方向键在当前结果集内切换，`Esc` 关闭。
有对应 MP4 的照片会直接用视频播放器打开（带播放控件），而不是显示静态图。

> 页面内所有链接均为**相对路径**，输出目录可以随意搬移、改名或分享 ——
> 只要 `index.html` 还和照片放在一起，页面就照常可用。

## 清理源文件（谨慎使用）

勾选「转换后清理源 .livp」后，全部转换成功的源文件会被移入**回收站**。
勾选时会弹出风险提示，并要求二次确认。

**请务必了解以下三点：**

1. **回收站不释放空间。** 文件进入回收站后仍占用磁盘，需要你手动清空
   回收站才会真正腾出空间。
2. **清空回收站即不可恢复。** `.livp` 是唯一能还原 HEIC 原图与原始视频的来源。
3. **JPG 是有损压缩。** 若画质设置偏高（数字偏小），转换后可能后悔。

**内置的安全保护：**

- 仅在**全部文件转换成功**后才开始清理
- 中途点「停止」或有任何失败 → **一个源文件都不会删**
- 逐个确认 JPG（及 MP4）已落盘且非空，才删除对应源文件
- 回收站空间不足时保留文件并如实报错，不会静默失败
- 该选项**不会随任务记录恢复**，每次启用都需重新确认
- 转换结束后自动取消勾选，不会误伤下一批任务

需要找回时，直接从回收站还原即可。

## 断点续传怎么用

1. 正常添加文件、选好输出目录，点「开始转换」
2. 转换途中可以直接关掉程序，或点「停止」
3. 下次打开，顶部会出现蓝色提示条，告诉你上次共几个、已完成几个、还剩几个
4. 直接点「开始转换」，已完成的会自动跳过，只跑剩下的

任务记录保存在程序目录下的 `.livp_state.json`（目录不可写时退回 `%LOCALAPPDATA%\LIVPConverter\`）。
点提示条上的「清除记录」或操作区的「清除记录」可删除，**不会影响任何已转换的文件**。

> 换了源文件或输出目录后重新添加即可覆盖旧记录。若想从零开始，点一次「清除记录」。

## 技术说明

### 为什么不用 `-map 0:v:0`

HEIC 文件内部包含多个视频流，**第一个流通常是 512×512 的缩略图**，
主图排在后面（实测 2316×3088 或 3024×4032）。

如果用常见的 `-map 0:v:0`，导出的是缩略图（30 KB 而非 1.5 MB），画质大打折。
本工具**不加 `-map`**，交给 ffmpeg 自动选择正确的流，才能拿到全尺寸主图。

### 依赖

- Python 3.8+（标准库 `zipfile` + `tkinter`）
- [ffmpeg](https://ffmpeg.org/download.html) —— 运行时从系统 PATH 探测，不打包进 exe

拍摄时间解析同样是**纯标准库**实现（`livp_meta.py` 手写 EXIF/TIFF 解析），
没有引入 Pillow 等依赖，exe 体积不受影响。

### 代码结构

| 文件 | 职责 |
|---|---|
| `livp_converter.py` | v1 入口：转换逻辑、后台线程、图形界面 |
| `livp_converter_v2.py` | v2 入口：同一套转换逻辑，换用改版界面 |
| `livp_ui.py` | v2 界面层。继承 v1 的界面类，转换逻辑不复制第二份 |
| `livp_meta.py` | 拍摄时间解析：EXIF → 文件名，不做不可信的猜测 |
| `livp_state.py` | 任务状态持久化，支撑断点续传（原子写入 + 版本号，避免回填过时的选项默认值） |
| `livp_contact.py` | 联系表生成：缩略图缓存与 HTML 页面，翻页与连续滚动共用一套切片渲染 |
| `livp_cleanup.py` | 可选的源文件清理，走 Windows 回收站（ctypes SHFileOperationW，绝不彻底删除） |
| `make_test_livp.py` | 开发用：生成测试 `.livp`，不参与打包 |
| `livp_estimate.py` | 基于实测单文件开销的耗时与体积估算；独立成模块以便测试 |

## 常见问题

**Q：下载 v1 还是 v2？**
下 v2。转换引擎一样，界面是新的。每个版本都仍附 v1，想用旧界面随时可以回退——
不过修 bug 改的是两者共用的代码，所以两边都受益。

**Q：提示「未找到 ffmpeg」？**
按上方说明安装 ffmpeg，或把 `ffmpeg.exe` 放到程序同目录。

**Q：HEIC 图片 Windows 打开不了？**
转换输出的是 **JPG**，任何设备都能直接打开，无需额外解码器。

**Q：转换会不会改动我的原文件？**
不会。程序只读取源文件，所有结果写入你指定的输出文件夹。

**Q：处理速度？**
约 1.2 秒/个（同时输出 JPG + MP4）。893 张约 18 分钟。

**Q：会读取我 HEIC 照片的拍摄时间吗？**
不会直接读取 —— HEIC 的 EXIF 未解析。文件名含时间戳的（`IMG_20260315_102333`）
处理正常；其余情况保留原文件名而不猜，并会在汇总里报告受影响的数量。

**Q：为什么不默认按日期分文件夹？**
因为 `2024云南2日游/` 这类相册目录通常比 `2024-07-02/` 更有意义，
按日期分层反而会打散它们。该选项是存在的，只是默认关闭 ——
只有源文件完全没有有意义的目录结构时才建议开启。
